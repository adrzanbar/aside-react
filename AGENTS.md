# AGENTS.md

Google Apps Script (V8) project, scaffolded from `@google/aside`, with a React/Vite UI inlined into the Apps Script HTML. Everything an agent edits here ends up as a single bundled IIFE pushed to a Google-hosted Apps Script via clasp.

## Commands

- `npm test` — Jest (ts-jest) on `test/` only, `--passWithNoTests`. Tests import `src/` directly; they do **not** exercise the bundle.
- `npm run lint` — ESLint (gts config) with `--fix` on `src/` and `test/` only. The `ui/` app is not covered here.
- `npm run build` — `clean` → rollup bundle → copy `appsscript.json` to `dist/` → build React ui → inline ui into `dist/ui.html` (via `deploy-ui.mjs`).
- `npm run deploy` — `lint` → `test` → `build`, then `ncp .clasp-dev.json .clasp.json` (overwrites working config) and `clasp push -f` to the dev script.
- `npm run deploy:prod` — same flow but uses `.clasp-prod.json` (which **does not exist** in the repo) and `clasp push` without `-f`; this script currently fails.
- No standalone typecheck script: `tsc` runs only inside `npm run build` (rollup-plugin-typescript2 on the backend, `tsc -b` inside `ui/`).

## How code becomes the deployed app

- Rollup bundles `src/index.ts` into `dist/index.js` as an IIFE named `$` (`rollup.config.mjs`).
- A custom `gas` plugin appends global wrapper functions, e.g. `function doGet(...args) { return $.doGet(...args); }`, for **every export of `src/index.ts`**. Those wrappers are the only things callable from Apps Script — so a new export becomes a global function in the deployed script, and names must not collide with Apps Script built-ins.
- The UI pipeline depends on two exports staying intact: `doGet` (serves the `ui` template) and `include` (inlines the bundled assets via `<?!= include('X.js'); ?>`). Removing or renaming either silently breaks the deployed UI.
- `src/example-module.ts` and `test/example-module.test.ts` are leftover scaffold: `index.ts` never imports the module, so it is tree-shaken out of the bundle. Editing it has no effect on what deploys.
- `dist/` is gitignored and regenerated by `build`; never hand-edit it.

## UI pipeline gotchas

- `ui/` is a separate Vite/React app with its own `package.json` and its own `node_modules` (two separate installs in this repo). `ui/` also uses oxlint (`npm run lint` inside `ui/`), not the root ESLint.
- `deploy-ui.mjs` rewrites the built `<script src=".../assets/X.js">` / `<link href=".../assets/X.css">` tags in `ui/dist/index.html` into `<?!= include('X.js'); ?>` templates and writes `dist/*.js.html` / `*.css.html`. It matches tags with a leading `./` or `/`, and captures whatever Vite names the assets (content hashes included), so the default Vite build works unchanged. Keep a single JS+CSS chunk: code-split chunks (modulepreload links) are not rewritten and will silently break the inline without a build error.
- `src/index.ts` `doGet` serves the `ui` template via `HtmlService.createTemplateFromFile('ui')`; `include(filename)` loads the generated `*.html`-suffixed files.
- The UI runs React 19 inside the Apps Script sandbox and uses React Router **Data Mode**: a `createMemoryRouter` built in `ui/src/routes.tsx` and rendered via `<RouterProvider>` in `ui/src/main.tsx`. Do not switch to `BrowserRouter` or to Framework Mode (`@react-router/dev`) — both are URL-driven and break in the sandboxed iframe.
- Data-mode route loaders/actions call the backend through `ui/src/gas.ts` (`callServer` → `google.script.run`). `google.script.run` is `undefined` in `vite dev`, so `callServer` throws and the route `ErrorBoundary` surfaces it — there is no mock-data layer.
- Do **not** use route `lazy` or dynamic imports in the UI: they add Vite chunks that `deploy-ui.mjs` cannot inline, silently breaking the deployed app.

## Config notes

- `.clasp.json` is generated/overwritten by the deploy scripts; edit `.clasp-dev.json` instead (both currently point to the same dev scriptId). Clasp pushes only `dist/` contents (`rootDir`); `.claspignore` is empty.
- `.clasp*.json` and `dist/` are gitignored; `appsscript.json` (timezone, V8 runtime) is copied into `dist/` at build time.
- Requires Node >= 22. Root `package.json` `main` points to `build/index.js`, which is stale and does not exist.
